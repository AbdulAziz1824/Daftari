# موقع فزعة — دليل النشر الكامل (GitHub + Vercel + Supabase)

هذا الدليل مكتوب لشخص خبرته صفر بهذه الأدوات. اتبع الخطوات بالترتيب تمامًا.

## الفكرة العامة قبل ما نبدأ

- **GitHub**: مكان تخزين أكواد المشروع (مثل "قوقل درايف" للأكواد).
- **Supabase**: قاعدة البيانات + نظام تسجيل الدخول + تخزين الصور (بديل Google Sheets + Drive).
- **Vercel**: الاستضافة اللي تشغّل الموقع فعليًا وتعطيك رابطًا (بديل نشر Web App في Apps Script).
- **Resend**: خدمة إرسال بريد التذكيرات (اختيارية، مجانية للاستخدام البسيط).

---

## الخطوة 1: إنشاء مشروع Supabase

1. اذهب إلى [supabase.com](https://supabase.com) وسجّل حساب مجاني (يمكنك الدخول بحساب Google).
2. اضغط **New Project**.
3. اختر اسمًا للمشروع (مثلاً `fazaa`)، وكلمة مرور لقاعدة البيانات (احفظها في مكان آمن)، واختر أقرب منطقة (Region) لك.
4. انتظر دقيقة حتى يجهز المشروع.

### تشغيل قاعدة البيانات
1. من القائمة الجانبية اختر **SQL Editor**.
2. اضغط **New query**.
3. افتح ملف `supabase-schema.sql` المرفق في هذا المشروع، انسخ **كل محتواه**، والصقه في المحرر.
4. اضغط **Run**. يجب أن تظهر رسالة نجاح (Success). هذا ينشئ كل الجداول (المستخدمين، الملفات، الأسئلة، الملاحظات، الاختبارات) وصلاحيات الحماية ومكان تخزين الصور دفعة واحدة.

### الحصول على المفاتيح
1. من القائمة الجانبية: **Project Settings** (⚙️) ← **API**.
2. ستحتاج ثلاث قيم، احتفظ بها لاستخدامها لاحقًا:
   - **Project URL** → هذا هو `NEXT_PUBLIC_SUPABASE_URL`
   - **anon public** key → هذا هو `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - **service_role** key (اضغط "Reveal" لإظهاره) → هذا هو `SUPABASE_SERVICE_ROLE_KEY` — **لا تشاركه مع أحد ولا تضعه في GitHub أبدًا**

### تفعيل تسجيل الدخول بدون تأكيد بريد (اختياري لتجربة أسرع)
افتراضيًا Supabase يرسل بريد تأكيد عند إنشاء حساب. إذا تبي تجرب الموقع بسرعة بدون هذه الخطوة:
1. **Authentication** ← **Providers** ← **Email**.
2. أوقف خيار **Confirm email**.
(يمكنك تفعيله لاحقًا عند الإطلاق الحقيقي لزيادة الأمان)

## الخطوة 2: رفع المشروع على GitHub

1. اذهب إلى [github.com](https://github.com) وسجّل حساب مجاني إن لم يكن لديك.
2. اضغط **+** أعلى الصفحة ← **New repository**.
3. اختر اسمًا (مثلاً `fazaa-web`)، اجعله **Private** إذا أردت، ثم **Create repository**.
4. على جهازك، فك ضغط المجلد الذي أرسلته لك (`fazaa-web.zip`).
5. افتح Terminal (أو Git Bash على ويندوز) داخل مجلد المشروع بعد فك الضغط، ونفّذ الأوامر التالية واحدًا تلو الآخر:

```bash
git init
git add .
git commit -m "أول نسخة من موقع فزعة"
git branch -M main
git remote add origin https://github.com/USERNAME/fazaa-web.git
git push -u origin main
```

استبدل `USERNAME` باسم حسابك على GitHub، و`fazaa-web` باسم المستودع الذي أنشأته.

> إذا لم يكن Git مثبتًا على جهازك، حمّله من [git-scm.com](https://git-scm.com) أولاً.
> بديل أسهل بدون Terminal: من صفحة المستودع على GitHub اضغط **uploading an existing file** واسحب كل الملفات والمجلدات يدويًا.

## الخطوة 3: النشر على Vercel

1. اذهب إلى [vercel.com](https://vercel.com) وسجّل دخول بحساب GitHub مباشرة (زر "Continue with GitHub").
2. اضغط **Add New** ← **Project**.
3. اختر المستودع `fazaa-web` الذي رفعته، واضغط **Import**.
4. قبل الضغط على Deploy، افتح قسم **Environment Variables** وأضف المتغيرات التالية (كل واحد بسطر):

| Name | Value |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | (من خطوة Supabase) |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | (من خطوة Supabase) |
| `SUPABASE_SERVICE_ROLE_KEY` | (من خطوة Supabase) |
| `RESEND_API_KEY` | (من خطوة Resend أدناه، أو اتركه فارغًا مؤقتًا) |
| `CRON_SECRET` | أي كلمة سر طويلة تختارها بنفسك |

5. اضغط **Deploy** وانتظر 1-2 دقيقة.
6. بعد الانتهاء ستحصل على رابط مثل: `https://fazaa-web.vercel.app` — هذا هو موقعك الجديد!

## الخطوة 4: إعداد بريد التذكيرات (Resend) — اختياري

1. اذهب إلى [resend.com](https://resend.com) وسجّل حساب مجاني.
2. من **API Keys** أنشئ مفتاحًا جديدًا وانسخه.
3. ارجع إلى مشروعك في Vercel ← **Settings** ← **Environment Variables** ← أضف/عدّل `RESEND_API_KEY` بالقيمة الجديدة.
4. اذهب إلى **Deployments** واضغط **Redeploy** على آخر نسخة حتى يُطبَّق المتغير الجديد.

> ملاحظة: الإعداد الحالي يرسل من عنوان تجريبي `onboarding@resend.dev` يعمل مباشرة بدون أي إعداد إضافي. إذا أردت لاحقًا الإرسال من بريد بنطاقك الخاص (مثل `noreply@fazaa.com`)، يلزمك ربط نطاق في Resend (خطوة متقدمة يمكن تأجيلها).

### جدولة الإرسال اليومي (موجودة مسبقًا)
ملف `vercel.json` في المشروع يخبر Vercel بتشغيل مسار `/api/send-reminders` كل يوم الساعة 6:00 صباحًا بتوقيت UTC تلقائيًا (Vercel Cron) — لا حاجة لأي إعداد إضافي، يعمل فور النشر. يمكنك تغيير التوقيت بتعديل السطر `"schedule"` في هذا الملف (بصيغة Cron) ثم إعادة الرفع.

---

## الخطوة 5: تجربة الموقع

1. افتح رابط Vercel الذي حصلت عليه.
2. اضغط "إنشاء حساب جديد" وسجّل ببريدك.
3. جرّب: إضافة ملف، إضافة سؤال بصورة، إضافة ملاحظة، إضافة اختبار، تفعيل التذكيرات من الإعدادات.

## الفروقات المهمة عن نسخة Google Apps Script

- **تسجيل الدخول أصبح بالبريد الإلكتروني** بدلاً من اسم مستخدم، لأن نظام المصادقة في Supabase مبني على البريد (أكثر أمانًا وموثوقية).
- **الصور تُخزَّن في Supabase Storage** بدلاً من Google Drive.
- **التذكيرات اليومية** تعمل عبر Vercel Cron + Resend بدل Triggers في Apps Script، وتعمل تلقائيًا بدون أي إعداد يدوي بعد أول نشر.
- **حذف الحساب** يحذف كل بياناته تلقائيًا من قاعدة البيانات بسبب إعداد `ON DELETE CASCADE`.

## كل مرة تبي تعدّل شيء بالموقع مستقبلًا

1. عدّل الملفات على جهازك.
2. نفّذ:
```bash
git add .
git commit -m "وصف التعديل"
git push
```
3. Vercel ينشر النسخة الجديدة تلقائيًا خلال ثوانٍ — لا حاجة لأي خطوة "Deploy > New version" كما في Apps Script.

## المشاكل الشائعة

- **صفحة بيضاء أو خطأ عند الفتح**: تأكد أن كل متغيرات البيئة (Environment Variables) مكتوبة بالضبط بدون مسافات زائدة في Vercel، ثم أعد النشر (Redeploy).
- **"Invalid API key"**: تأكد أنك نسخت `anon public` وليس `service_role` في `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
- **الصور لا تُرفع**: تأكد أن كود SQL الخاص بـ Storage (آخر جزء في `supabase-schema.sql`) نُفِّذ بنجاح بدون أخطاء.
- **لا يصل بريد التذكير**: تأكد من وجود `RESEND_API_KEY` في Vercel وأنك فعّلت التذكيرات من صفحة الإعدادات ببريد صحيح.

## تحديث V1.05 (المطور + سجل الدخول)

1. شغّل ملف `supabase-v1.05.sql` في Supabase > SQL Editor.
2. التحديث التلقائي صار كل 5 دقائق (بدل 5 ثوانٍ) وخانة "آخر تحديث" بجانب زر التحديث.
3. تبويب **المطور** في شريط التنقل يظهر للأدمن فقط: الحسابات (مع آخر جهاز)، سجل الدخول، البلاغات.
4. إنشاء حساب مطور من الطرفية: `node --env-file=.env.local scripts/create-dev-admin.mjs USERNAME PASSWORD`
